# Fixes applied — 2026-09-04

## Fixed

**`backend/src/test/java/com/neelastack/service/InvoiceServiceTest.java`**
Root cause of all `InvoiceServiceTest` failures (3 failures, 3 errors) in both the
local Maven run and the `backend-tests` CI job.

`InvoiceService.createOrder()` and `InvoiceService.verifyAndConfirmPayment()` both
call the private helper `getInvoiceWithAccessCheck()` first, which does an
*unlocked* `invoiceRepository.findById(...)` read, before separately doing a
*locked* `invoiceRepository.findByIdForUpdate(...)` read for the actual mutation.

The tests only stubbed `findByIdForUpdate` — `findById` was never stubbed, so
Mockito returned `Optional.empty()` for it and every test threw
`ResourceNotFoundException` at the access-check step, before ever reaching the
behavior under test.

Fix: the shared `invoiceWithOrder(...)` test helper now stubs both
`findById(...)` and `findByIdForUpdate(...)` for the invoice it builds. All 8
tests that construct an invoice via this helper are covered by the one change.

The Testcontainers/Docker errors in the local run (`Could not find a valid
Docker environment`) are unrelated — that's Docker Desktop not running on the
local Windows machine, not a code issue. GitHub Actions runners have Docker
preinstalled, so `backend-tests` in CI was failing on the mock-stub bug above,
not on Testcontainers itself.

## Investigated, not changed — needs a deliberate follow-up

**Frontend `npm audit` (24 high, 1 critical, on Angular 19.2.25).**
The real fixes for the high/critical CVEs (hydration DOM-clobbering, i18n XSS,
HttpTransferCache cache-key poisoning) only ship in Angular 21 — three majors
ahead of this project. `npm audit fix --force` rewrites `package.json` to an
inconsistent mix of Angular majors (core `^21.2.22` alongside
platform-browser-dynamic `^20.0.7` and ssr `^22.1.7`), which does not form a
buildable Angular app. I tried this, confirmed it breaks the dependency graph,
and reverted it — `package.json`/`package-lock.json` in this zip are unchanged
from before, and `npm ci` installs cleanly.

This needs a real migration: `ng update @angular/core@20 @angular/cli@20`,
verify the app builds and the test suite passes, then repeat for `@21`. Doing
that blind, without being able to run the full build/test/E2E suite to verify
each step, isn't something to bundle into an automated fix pass.

**Backend OWASP Dependency-Check job (`dependency-scan-backend`).**
Fails with no `dependency-check-report.html` produced. Per the workflow's own
comment, this is almost certainly the missing `NVD_API_KEY` repository secret —
without it, NVD's feed update gets rate-limited before the plugin can scan
anything, and the failure looks identical to "a real CVE ≥ 8 was found." This
is a GitHub repo secret to add (Settings → Secrets and variables → Actions →
`NVD_API_KEY`, from https://nvd.nist.gov/developers/request-an-api-key), not a
code change.

**CodeQL (java-kotlin) autobuild failure from the CI log.**
The `.github/workflows/ci-cd.yml` already in this repo uses `build-mode: manual`
with an explicit `mvn -B clean compile -DskipTests` step for the java-kotlin
matrix leg — the correct fix for the "unable to automatically build your code"
autobuild error. That failure in the log doesn't match this workflow file, so
it looks like it's from a run before that fix landed. Nothing further to do
here unless it recurs against this exact workflow.
